# 脱敏策略设计文档

> 版本：v2.0 | 生效日期：2026-08-25
> 参考基线：《03-代码生成规范》敏感字段约定。

v2 相对 v1 的调整：全局敏感词列表移除，改为**表级 `columns[].sensitive + sensitiveStrategy` 配置**；敏感列由 Assembler 从响应中剔除，查询条件不含敏感列。

---

## 一、核心原则

**"脱敏发生在系统的出口，而不是入口或内部。"**

- 数据库、领域模型、业务逻辑层 **始终保持数据的原始性**
- 只有**数据离开系统边界**（返回前端、打印日志）时才执行脱敏
- 敏感列**不进响应、不进查询条件、不进日志**；确实需要展示时用 `@Sensitive` 策略脱敏

---

## 二、脱敏分层

| 层级 | 数据状态 | 是否脱敏 |
| :--- | :--- | :---: |
| 数据库 | 原始数据 | ❌ |
| DO / Repository | 原始数据 | ❌ |
| Domain Model | 原始数据 | ❌ |
| Core-Service / Biz | 原始数据 | ❌ |
| 查询条件 | 不含敏感列 | — |
| 日志打印 | 脱敏后 / 白名单 | ✅ |
| Controller 返回 | 剔除或脱敏 | ✅ |

---

## 三、脱敏策略枚举

| 策略值 | 显示名称 | 脱敏规则 | 示例 |
| :--- | :--- | :--- | :--- |
| `NONE` | 不脱敏 | 原样输出 | `张三` → `张三` |
| `PHONE` | 手机号 | 保留前3后4 | `13812345678` → `138****5678` |
| `ID_CARD` | 身份证号 | 保留前6后4 | `110101199003071234` → `110101********1234` |
| `BANK_CARD` | 银行卡号 | 保留前4后4 | `6222***1234` |
| `EMAIL` | 邮箱 | 保留前3和域名 | `zha***@qq.com` |
| `NAME` | 姓名 | 保留姓氏 | `张**` |
| `ADDRESS` | 地址 | 保留前6字符 | `浙江省杭*****` |
| `PASSWORD` | 密码 | 完全脱敏 | `******` |
| `CUSTOM` | 自定义 | 用户自定义正则 | 自行配置 |

---

## 四、实现方式

### 响应脱敏（@JsonSerializer）

```java
@Data
public class User {
    @Sensitive(strategy = SensitiveStrategy.PHONE)
    private String phone;   // 13812345678 → JSON 输出 138****5678
}
```

### 日志脱敏（Logback Converter）

```xml
<conversionRule conversionWord="msg" converterClass="SensitiveMessageConverter"/>
```

## 五、v2 敏感字段处理（生成器约束）

### 5.1 配置方式（表级，无全局敏感词）

在 `generate.yaml` 的 `tables[].columns` 中逐列配置：

```yaml
columns:
  id_card:
    sensitive: true
    sensitiveStrategy: ID_CARD       # PHONE | ID_CARD | BANK_CARD | EMAIL | NAME | ADDRESS | PASSWORD | NONE
  phone:
    sensitive: true
    sensitiveStrategy: PHONE
```

> v1 的全局 `sensitive_columns` 已移除；只有配置了 `sensitive: true` 的列才按敏感列处理。

### 5.2 各层处理规则

| 位置 | 处理方式 |
| :--- | :--- |
| DO / Model | **保留原值**（登录校验等场景需要读取） |
| 创建 / 更新请求 DTO | 保留敏感字段，但**不作为查询入口** |
| 查询参数 / 查询条件 | **剔除**（不允许按密码、token 等过滤） |
| 响应 DTO | **剔除**；明确需要展示时用 `@Sensitive(strategy = ...)` 脱敏（Assembler 首行判空、敏感列不进响应） |
| 日志 | 只打白名单字段，**禁止打印完整参数/结果对象**（含密码） |

### 5.3 生成器默认行为

- 敏感列自动从查询参数、响应和查询条件中剔除；
- 响应序列化脱敏走 `@Sensitive(strategy = ...)`（见上文策略枚举）；
- 日志脱敏走 Logback `SensitiveMessageConverter`；
- 生成后的每个模块都必须满足：**敏感字段不出现在响应、查询和日志中**。
