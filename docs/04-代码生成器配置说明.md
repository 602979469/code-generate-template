## 一、完整配置结构

```yaml
# ============================================================
# generate.yaml — code-generate-template 配置模板（全配置项）
# 用法:
#   1) 首次运行 ./gen.sh 生成本文件与 example.sql
#   2) 先执行 example.sql 创建示例表（example_inner / example_logic / example）
#   3) 编辑项目命名与 jdbc 后运行: ./gen.sh ./generate.yaml
# ============================================================

# ---------------- 项目命名（全部必填，无默认值） ----------------

# 项目前缀（驼峰，用于启动类名），如 AiProd -> AiProdApplication
projectPrefix: AiProd

# Maven groupId
groupId: com.jakt

# artifactId/包名后缀（小写字母/数字，Java 包名不允许连字符）
projectArtifactPrefix: aiprod

# 基础包名
basePackage: com.jakt.aiprod

# ---------------- 项目架构风格（可选，默认 monolith:flat） ----------------

# 项目风格: monolith（microservice 暂未实现，配置到即报错）
projectStyle: monolith

# 模块样式: flat（本期仅支持 flat；aggregated / maven-module 暂未实现，配置到即报错）
#   业务模块作为层内子包: com.jakt.aiprod.core.model.chat.domain
moduleLayout: flat

# ---------------- 业务模块列表（声明有哪些模块，供表关联选择） ----------------
modules:
  - name: chat
    displayName: 聊天模块
  - name: auth
    displayName: 认证模块
  - name: ai
    displayName: AI 模块

# ---------------- 数据库（配置了 tables 时必填） ----------------
jdbc:
  url: jdbc:mysql://localhost:3306/aiprod?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
  username: root
  password: "123456"

# 生成输出根目录（项目骨架 init 与表级 CRUD 的落点）
outputDir: /Users/jakt/IdeaProjects/AiProd

# ---------------- 全局逻辑删除（可选，默认不开启） ----------------
# enable: true 时 column_name / normal_value / delete_value 三项必填（前置校验）；
# 表级 tables[].logicDelete 可覆盖全局（示例见下方 example_logic）。
globalLogicDelete:
  enable: false
  column_name: del_flag
  normal_value: 0
  delete_value: 1

# ---------------- 插件（可选，工程级一次性生成） ----------------
# 声明插件后，生成器向工程注入对应业务代码（目标落 common-framework / common-util 包），
# 已生成过的文件跳过、不覆盖；插件不负责表，涉及表的业务走下方 tables 配置。
plugins:
  - name: sa-token
    # config:  # 参数预留位（第一版固定模板，暂不传参）

# ---------------- 业务表（每张表只需 db_table_name） ----------------
# model_name 缺省 = 表名驼峰（如 example_logic -> ExampleLogic）
# model_comment 缺省 = 数据库表注释（生成代码的所有注释都用它拼接）
# module: 可选，关联上方 modules 配置；不填 = 业务层路径不带模块段（1.0 原样），
#         填写后业务模块作为层内子包（如 core.model.chat.domain）
# 下方三张示例表覆盖全部可选配置项:
#   example_inner  -> generateController: false（内部表，不生成 web 层）
#   example_logic  -> logicDelete（逻辑删除，仅默认类型映射，不配置 columns）
#   example        -> force_create + columns（枚举 / json / jsonArray / jsonObject / 强制类型转换 / 表级敏感列）
tables:
  # 1) 内部表: 不提供 Controller，只生成数据/服务层文件；model_name/model_comment 显式指定
  #    force_create: true 演示"内部表 + 强制覆盖"组合（危险：会覆盖该表已存在文件）
  - db_table_name: example_inner
    module: chat                          # 关联 modules 中的 chat 模块
    model_name: ExampleInner
    model_comment: 内部示例
    generateController: false
    force_create: true

  # 2) 逻辑删除表: 只做默认类型映射，不指定转换方式；deleteById 变 UPDATE
  #    仅配置 db_table_name + module，model_name/model_comment 走缺省（表名驼峰 + 数据库表注释）
  - db_table_name: example_logic
    module: auth                          # 关联 modules 中的 auth 模块
    logicDelete:
      enable: true
      column_name: del_flag
      normal_value: 0
      delete_value: 1

  # 3) 全功能表: 非逻辑删除，演示全部列级转换 + force_create
  #    force_create: true 会覆盖该表已存在文件（危险，演示用）
  - db_table_name: example
    module: ai                            # 关联 modules 中的 ai 模块
    model_name: Example
    model_comment: 示例
    force_create: true
    columns:
      # 枚举: int 列 -> UserTypeEnum，Model/DTO 用枚举，DO 保持 Integer
      # codeType 已移除，枚举 code 的类型由 values 中的 code 自动推断
      user_type:
        type: enum
        enum:
          className: UserTypeEnum
          values:
            - { code: 0, name: SYSTEM_USER, desc: 系统用户 }
            - { code: 1, name: NORMAL_USER, desc: 普通用户 }
      # 枚举: varchar 列 -> UserStatusEnum
      status:
        type: enum
        enum:
          className: UserStatusEnum
          values:
            - { code: ENABLED, name: ENABLED, desc: 启用 }
            - { code: DISABLED, name: DISABLED, desc: 停用 }
      # 强制类型转换: bigint -> Integer（Convert.toInt），也可 Long/BigDecimal/String
      login_count:
        type: Integer
      # 敏感字段: 表级配置脱敏策略（全局敏感词已移除，仅表级可配置）
      id_card:
        sensitive: true
        sensitiveStrategy: ID_CARD       # PHONE | ID_CARD | BANK_CARD | EMAIL | NAME | ADDRESS | PASSWORD | NONE
      phone:
        sensitive: true
        sensitiveStrategy: PHONE
      # jsonObject: javaObject 填目标对象类型（POJO 全限定名或 Map<String, Object>），缺省 Map<String, Object>
      # 注意: javaObject 指向的 POJO 需自己创建（如 com.jakt.aiprod.core.model.domain.Profile）
      profile:
        type: jsonObject
        javaObject: com.jakt.aiprod.core.model.domain.Profile
      # jsonArray: javaObject 填元素类型（POJO 全限定名或 String / Integer / Double 等基础类型）
      tags:
        type: jsonArray
        javaObject: com.jakt.aiprod.core.model.domain.Tag
      # json: 保持原始字符串
      extra:
        type: json
```

## 二、路径映射规则（v2 统一口径）

### 2.1 核心规则

包路径由以下要素共同决定：

```yaml
projectStyle: monolith          # monolith（microservice 暂未支持）
moduleLayout: flat              # flat（本期仅支持 flat；aggregated / maven-module 暂未实现）
basePackage: com.jakt.aiprod    # 全局基础包名
module: chat                    # 表所属业务模块（表级配置，可空）
```

> 本期仅 `flat` 生效；`aggregated / maven-module` 的路径公式为设计约定，暂未实现（配置到即报错）。

计算公式（与 `LayoutStrategy.resolve()` 实现一致）：

```text
共享层                = {basePackage}.{层包}.{子包}        # common.* 不挂业务模块
flat                  = {basePackage}.{层包}.{module}.{子包}
aggregated/maven-module = {basePackage}.modules.{module}.{层包}.{子包}
module 为空            = 路径不含业务模块段（flat 等价 1.0 原样）
输出目录               = {outputDir} + {模块根目录} + /src/main/java/ + {包路径转文件路径}
```

### 2.2 三种样式对照表

| 样式 | 布局前缀 | 模块根目录（业务层） | 包路径 | 完整示例 |
| --- | --- | --- | --- | --- |
| flat | 空 | 1.0 层模块（common/dal、core/model、web…），业务模块为层内子包 | {basePackage}.{层包}.{module}.{子包} | com.jakt.aiprod.core.model.chat.domain.ChatMessage |
| aggregated（未实现） | modules | {outputDir}/modules/{projectArtifactPrefix}-{module}/ | {basePackage}.modules.{module}.{层包}.{子包} | com.jakt.aiprod.modules.chat.web.controller.ChatMessageController |
| maven-module（未实现） | modules | {outputDir}/{projectArtifactPrefix}-{module}/（平铺） | {basePackage}.modules.{module}.{层包}.{子包} | 同 aggregated（仅目录位置不同） |

### 2.4 三种模式目录结构对比

flat（平铺式，不新建 Maven 模块）：

```text
{outputDir}/
├── common/
│   ├── dal/src/main/java/com/jakt/aiprod/common/dal/        # dataobject / mapper / query
│   ├── integration/src/main/java/com/jakt/aiprod/common/integration/
│   └── util/src/main/java/com/jakt/aiprod/common/util/
├── core/
│   ├── model/src/main/java/com/jakt/aiprod/core/model/      # chat|auth|ai → domain / param
│   ├── repository/src/main/java/com/jakt/aiprod/core/repository/  # chat|auth|ai → repository / impl / convertor
│   └── service/src/main/java/com/jakt/aiprod/core/service/  # chat|auth|ai → service / impl
├── biz/service-impl/src/main/java/com/jakt/aiprod/biz/service/   # chat|auth|ai → service / impl
├── web/src/main/java/com/jakt/aiprod/web/                   # chat|auth|ai → controller / checker / param / result / assembler
```

aggregated（聚合式，业务模块子项目收在 modules/ 下）：

```text
{outputDir}/
├── pom.xml
├── common/                      # 共享模块（同 flat）
├── modules/
│   ├── aiprod-chat/
│   │   └── src/main/java/com/jakt/aiprod/modules/chat/
│   │       ├── web/             # controller / checker / param / result / assembler
│   │       ├── core/            # model / repository / service
│   │       └── biz/             # service / impl
│   ├── aiprod-auth/…
│   └── aiprod-ai/…
└── bootstrap/
```

maven-module（业务模块子项目平铺在根下）：

```text
{outputDir}/
├── pom.xml
├── common/                      # 共享模块
├── aiprod-chat/
│   └── src/main/java/com/jakt/aiprod/modules/chat/
│       ├── web/                 # controller / checker / param / result / assembler
│       ├── core/                # model / repository / service
│       └── biz/                 # service / impl

├── aiprod-ai/…
└── bootstrap/
```

### 2.5 路径映射速查表

| 模式 | 模块根目录 | 包路径前缀（业务层） | Application |
| --- | --- | --- | --- |
| flat | 1.0 层模块（不新建） | {basePackage}.{层包}.{module} | 1 个 |
| aggregated | {outputDir}/modules/{projectArtifactPrefix}-{module}/src/main/java | {basePackage}.modules.{module}.{层包} | 1 个 |
| maven-module | {outputDir}/{projectArtifactPrefix}-{module}/src/main/java | {basePackage}.modules.{module}.{层包} | 1 个 |

### 2.6 路径生成伪代码（统一口径）

```java
public PathSpec resolve(String layerPackage, String sub, String module) {
    String pkg;
    if (layerPackage.startsWith("common.")) {
        // 共享层不挂业务模块
        pkg = basePackage + "." + layerPackage + "." + sub;
    } else if (isBlank(module)) {
        // 未分配业务模块：路径不含模块段（flat 等价 1.0 原样）
        pkg = basePackage + "." + layerPackage + "." + sub;
    } else if (layout.equals("flat")) {
        pkg = basePackage + "." + layerPackage + "." + module + "." + sub;
    } else { // aggregated / maven-module：包路径一致，仅根目录不同
        pkg = basePackage + ".modules." + module + "." + layerPackage + "." + sub;
    }
    return new PathSpec(strategy.moduleRoot(outputDir, module), pkg);
}
```

## 三、各配置项详解
### 3.1 项目基础信息

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| projectPrefix | string | ✅ | 项目前缀，驼峰，用于启动类名 |
| groupId | string | ✅ | Maven groupId |

| basePackage | string | ✅ | 基础包名，所有代码的根包 |
| projectStyle | string | ❌ | monolith（默认；microservice 暂未实现） |
| moduleLayout | string | ❌ | flat（默认；aggregated / maven-module 暂未实现） |
| outputDir | string | ✅ | 生成输出根目录 |

### 3.2 业务模块列表

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | ✅ | 模块唯一标识，小写字母/数字 |
| displayName | string | ✅ | 中文显示名 |

### 3.3 全局逻辑删除

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enable | boolean | false | 是否启用逻辑删除 |
| column_name | string | del_flag | 逻辑删除字段名 |
| normal_value | int | 0 | 正常值 |
| delete_value | int | 1 | 删除值 |

### 3.4 表定义

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| db_table_name | string | ✅ | 数据库表名 |
| module | string | ❌ | 所属模块，与 modules[].name 匹配；flat 下不填 = 路径不带模块段 |
| model_name | string | ❌ | 模型类名，缺省自动生成 |
| model_comment | string | ❌ | 模型注释，缺省读表注释 |
| generateController | boolean | ❌ | 是否生成 Controller，默认 true |
| force_create | boolean | ❌ | 是否强制覆盖，默认 false |
| logicDelete | object | ❌ | 覆盖全局逻辑删除 |
| columns | object | ❌ | 字段自定义配置 |

### 3.6 插件（plugins）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 插件名，对应 `templates/plugins/{name}/`；声明后工程级一次性生成，已存在文件跳过不覆盖 |
| config | object | 参数预留位（第一版固定模板，暂不传参） |

> 插件协议（plugin.yaml 目标文件清单 / maven 依赖、生成行为）见《08-代码生成器架构扩展设计》第四章。

### 3.5 字段配置

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | string | enum / json / jsonObject / jsonArray / Integer / Long / String / BigDecimal |
| enum.className | string | 枚举类名 |
| enum.values | list | { code, name, desc } |
| sensitive | boolean | 是否脱敏 |
| sensitiveStrategy | string | PHONE / ID_CARD / BANK_CARD / EMAIL / NAME / ADDRESS / PASSWORD / NONE |
| javaObject | string | jsonObject/jsonArray 的目标 Java 类型全限定名 |
| maxLength | int | 预留：生成 @Size(max=...) |
| nullable | boolean | 预留：生成 @NotNull |
| queryable | boolean | 预留：是否支持查询 |
| queryType | string | 预留：eq / like / range |
本配置说明由架构组维护。
