## 二、命名与类型转换规则

| 转换类型 | 规则 | 示例 |
| :--- | :--- | :--- |
| 表名 → ModelName | snake → PascalCase，**无前缀** | `chat_message` → `ChatMessage` |
| 字段名 → Java 字段 | snake → camelCase | `create_time` → `createTime` |
| 数据库类型 → Java 类型 | 类型映射表（见下） | `varchar` → `String`，`datetime` → `LocalDateTime` |

### 2.1 数据库默认映射（未配置 `columns` 时）

| 数据库类型 | Java 类型 |
| :--- | :--- |
| `bigint` | `Long` |
| `int` / `smallint` / `tinyint` | `Integer` |
| `varchar` / `char` / `text` / `longtext` | `String` |
| `datetime` / `timestamp` | `LocalDateTime` |
| `date` | `LocalDate` |
| `decimal` / `numeric` | `BigDecimal` |
| `double` / `float` | `Double` |
| `bit` / `boolean` | `Boolean` |
| `json` | `String`（原始 JSON 文本） |

优先级：列级 `columns` 配置 > 数据库默认映射（默认映射不开放为风格开关）。

### 2.2 列级配置

**枚举（`type: enum`）**

- `enum.className` 必填且为合法 Java 类名；`values` 中 `code` / `name` / `desc` 均必填，`code` 与 `name` 不可重复；
- 枚举 code 类型按列推断：int 族 → `Integer`、bigint → `Long`、其余 → `String`；
- DO 保持原始类型（Integer/String），Model/DTO 用枚举，Convertor 自动 `fromCode(...)` / `getCode()` 双向转换；
- 同名枚举已存在且未 `force_create` → 跳过该枚举文件（不覆盖）；**检测按模块隔离**——同模块内多表共用同一枚举只生成一次，跨模块允许同名枚举各自生成（如 chat / auth 各有 `EnableStatusEnum`）。

**JSON（`type: json / jsonObject / jsonArray`）**

- `json`：保持原始字符串，不解析；
- `jsonObject`：`javaObject` 为目标 POJO 全限定名或 `Map<String, Object>`；
- `jsonArray`：`javaObject` 为元素类型（POJO / `String` / `Integer` 等），生成 `List<X>`；
- 绑定的 POJO 由业务方自行创建，生成器不产出；Convertor 自动用 `JsonUtil.parseArray / parseObject / parseMap / toJson` 互转。

**强制类型转换（`type: 具体 Java 类型`）**

- 支持 `Integer / Long / BigDecimal / String / Double / Boolean / Float / Short / Byte / Character`；
- DO 类型不变，Model/DTO 为指定类型；转换统一使用 Hutool `Convert`（`toInt / toLong / toStr` 等），禁止裸 `Integer.valueOf` 等。

## 三、生成器核心流程

```text
读取配置（generate.yaml）
│
▼
连接数据库，读取表结构
│
▼
命名转换引擎
├── 表名 → ModelName（无前缀）
├── 字段名 → Java 字段
├── 数据库类型 → Java 类型
└── 衍生类名生成
│
▼
路径计算引擎（LayoutStrategy）
├── 共享层：{basePackage}.common.*（不挂业务模块）
├── flat：{basePackage}.{module}.{层包}.{子包}
├── aggregated / maven-module：{basePackage}.modules.{module}.{层包}.{子包}
└── module 为空：路径不含业务模块段
│
▼
模板渲染
├── 组装数据模型
├── 敏感列识别与剔除（表级 sensitive + sensitiveStrategy）
├── 校验推导（NOT NULL / varchar 长度 / 非自增主键）
└── Freemarker 渲染
│
▼
文件输出（幂等防覆盖）
└── 已存在且未 force_create → 跳过；force_create → 覆盖并警告
```

## 四、校验推导规则（v2）

| 列特征 | 推导结果 |
| :--- | :--- |
| `NOT NULL` 且无默认值 | 请求 DTO 生成 `@NotBlank`（字符串）/ `@NotNull`（其他类型） |
| `varchar(N)` | 请求 DTO 生成 `@Size(max = N)` |
| 非自增主键 | CreateRequest 自动必填，INSERT 显式携带主键列 |
| 枚举列 | 必须配置 `columns.type: enum`；生成枚举 `fromCode` / `getCode`（Convertor 双向转换） |
| 敏感列 | 从查询参数、响应、查询条件中剔除（表级 `sensitive: true`） |
| json 系列列 | 不进查询条件（`queryType=NONE`），避免 JSON 文本等值比较；Model/DO 仍保留 |

## 五、SQL 与生成语义（v2）

- `create_time` / `update_time`：由数据库自动维护（`DEFAULT CURRENT_TIMESTAMP [ON UPDATE CURRENT_TIMESTAMP]`）；未满足时生成代码在 INSERT/UPDATE 显式 `NOW()` 并输出警告，不阻塞生成；
- `create_by` / `update_by`：**按普通业务列生成**（v2 不设计审计字段，由业务自行决定）；
- `del_flag`：仅作为逻辑删除列由 SQL 层管理（配置 `logicDelete` 时生效），不生成 DO 字段；
- 逻辑删除：`logicDelete` 配置的列必须真实存在才启用；缺失时生成器输出警告并**退化为物理删除**（不静默忽略）；`deleteById` 变 UPDATE；
- 查询条件当前全部等值 `=`（含 varchar），另含创建/更新时间区间（`createTimeBegin / createTimeEnd / updateTimeBegin / updateTimeEnd`）与分页；
- `insert`：全字段插入；`update`：全量更新；`updateByCondition`：按非空字段条件更新；
- `findOne`：结果必须唯一，多条报错，零条返回 null；`findList / findPage`：返回 `List` / `PageResult<core-model>`；
- 仓储返回值：`insert` 返回回填主键后的 Model，`update/updateByCondition/deleteByXxx` 返回 `int`；
- `generateController: false`（内部表）：不生成 web 层与 biz 层文件；
- 生成器不生成测试代码。
