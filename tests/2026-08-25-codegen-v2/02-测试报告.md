| 文档一致性 | ⚠️ create_by/update_by 处理与文档冲突（见问题 3） |

## 四、问题清单

### 问题 1 [高] Convertor 查询链路缺少转换表达式（编译阻断）

**现象**：`toDalQuery()` 对强制类型转换列、jsonObject/jsonArray 列做裸赋值，类型不匹配，生成工程无法编译。

**证据**：

- 真实配置（flat）：`AuthLoginLogConvertor.java:81`
  `target.setUserId(source.getUserId())` —— QueryParam 为 `Integer`（配置 `type: Integer`），DalQuery 为 `Long`。
  用户现有工程 `/Users/jakt/IdeaProjects/AiProd/core/repository/src/main/java/com/jakt/aiprod/core/repository/convertor/AuthLoginLogConvertor.java:81` 同样报 `不兼容的类型: java.lang.Integer无法转换为java.lang.Long`。
- 示例配置：`ExampleConvertor.java:101/105/106`，三处：
  - `setLoginCount(...)` Integer→Long（强制转换列）
  - `setProfile(...)` Profile→String（jsonObject）
  - `setTags(...)` List<Tag>→String（jsonArray）

**根因**：`DbMetaReader.applyColumnConfigs` 只对 `enum` 设置了 `toDalExpr`；`COERCE`、`JSON_OBJECT`、`JSON_ARRAY` 未设置，回落到默认的 `{query}.getX()`。

**修复建议**：

- COERCE：`toDalExpr = Convert.toX({query}.getX())`（X = 数据库原始 Java 类型）；
- JSON_OBJECT / JSON_ARRAY：`toDalExpr = JsonUtil.toJson({query}.getX())`；
- 同时考虑 json 列不进查询条件（或仅按原始串等值），避免 Mapper.xml 出现 `profile = #{profile}` 的 JSON 等值比较。

### 问题 2 [高] aggregated / maven-module 缺少 Maven 装配，业务代码不在构建内

**现象**：两种布局生成目录/包路径与文档一致，但业务模块目录（`modules/aiprod-*` 或 `aiprod-*`）**没有 pom.xml**，根 pom 的 `<modules>` 仍是 flat 的 web/biz/core/common/bootstrap，骨架还会把 flat 的空层模块复制一份。实测 `mvn compile` 成功但业务代码完全没被编译。

**证据**：

- `/tmp/cgt-test/out-maven/aiprod-ai/` 只有 `src/`，无 pom；
- `/tmp/cgt-test/out-maven/pom.xml` `<modules>` 只含 web/biz/common/core/bootstrap。

**修复建议**：按布局差异生成骨架——为每个业务模块生成 pom（artifactId、依赖 common 模块等）、把业务模块挂进根 pom、bootstrap 依赖业务模块；非 flat 布局不再复制 flat 的 web/biz/core 空模块。属于较大改动，需确认骨架形态后实施；或先在文档中标注“未实现”。

### 问题 3 [中] create_by / update_by 文档与实现冲突

**现象**：文档《07-映射引擎设计》规定 `create_by / update_by / del_flag` 为保留审计列、不生成 DO 字段；实现将 `create_by / update_by` 按普通业务列生成。

**证据**：`SysAiCapabilityDO.java` 含 `createBy` / `updateBy`，对应 CreateRequest/查询/响应均出现。

**修复建议**：二选一——代码对齐文档（加入保留列集合，不生成 DO 字段），或文档对齐实现（明确 create_by/update_by 按业务列生成）。需用户决策。

### 问题 4 [中] `--validate` 不校验布局组合，且正式生成先落骨架再报错

**现象**：`projectStyle: microservice`、`moduleLayout: bogus` 在 `--validate` 下全部“通过”，正式生成时才抛“暂未支持/不支持的 moduleLayout”；且正式生成先执行 SkeletonGenerator（已写盘 63 个文件）再在 CrudGenerator 失败，留下半成品骨架。

**根因**：校验路径不构造 PathResolver/layoutStrategy；布局校验时机在骨架初始化之后。

**修复建议**：在 `validateNaming()`（或 Main 骨架初始化之前）调用 `cfg.layoutStrategy()` 提前拦截；`--validate` 同样生效。

### 问题 5 [中] example.sql 与 generate.yaml.example 列定义不一致

**现象**：配置模板为 `example` 表配置了 `id_card` / `phone` 脱敏列，但 example.sql 建表没有这两列，`--validate` 直接报“列不存在”。

**证据**：初次校验 `✗ example: 列 id_card 不存在于表 example`；本次测试在 `aiprod.example` 表手工补列后通过。

**修复建议**：example.sql 的 `example` 表补充 `id_card varchar(18)`、`phone varchar(20)` 列（与配置模板对齐），或删除配置中这两列。

### 问题 6 [中] 逻辑删除值与真实库语义不一致

**现象**：真实库 `del_flag` 注释为“0存在 2删除”，而 generate.yaml 全局及表级均为 `delete_value: 1`。生成的删除 SQL 将行标记为 1，与库内既有数据语义（2）冲突，且 `del_flag=2` 的历史行不会被查询过滤。

**修复建议**：确认库语义后将配置改为 `delete_value: 2`（同时影响全局与表级覆盖）。

### 问题 7 [低] 共享枚举跨模块重复

**现象**：`EnableStatusEnum` 在 chat / auth / ai 三个模块各生成一份（`core/model/{module}/enums/`）。模块隔离下可接受，但与“多表共用同一枚举只生成一次”的表述不完全一致，跨模块缺少共享机制。

**建议**：明确设计意图——共享枚举落公共层（如 common-framework.enums）或保持模块内复制。

### 问题 8 [低] plugins 配置被静默忽略

**现象**：GeneratorConfig 无 plugins 字段，`plugins: - name: sa-token` 不报错也无任何提示。

**建议**：按文档“协议就绪、实现后续落地”，至少输出一条“插件暂未实现”警告。

### 问题 9 [低] `--validate` 不显示 del_flag 缺失告警

**现象**：生成模式下 auth_login_log / auth_role_menu / auth_user_role / sys_ai_capability 均提示“逻辑删除已开启但表中不存在列 del_flag，退化为物理删除”；校验模式不显示该信息。

**建议**：校验模式与生成模式告警口径一致。

### 问题 10 [低] `--structure` 占位文件与正式生成互斥

**现象**：structure 模式生成 0 字节占位文件，随后在同一 outputDir 正式生成时，非 force_create 的表被整表跳过（实测 aggregated 的 example_logic 只留下空占位文件）。

**建议**：structure 模式输出到独立目录，或在正式生成时提示并清理占位文件。

## 五、验证正确的关键项（回归基线）

- 敏感列四层处理：CreateRequest 保留 password/email/avatar，QueryRequest/Response/QueryParam 剔除（AuthUser 实测）；
- 逻辑删除 SQL：char 列加引号（`del_flag = '0'`）、deleteById 转 UPDATE、查询过滤；
- 时间列策略：非自动维护表 INSERT/UPDATE 显式 `NOW()`（ai_chat_message 实测）；
- 复合主键关联表：ByKey 全键 CRUD、`generateController:false` 时 11 文件；
- 枚举：DO 保持数据库原始类型、Model/DTO 用枚举、Convertor `fromCode/getCode` 双向转换、同模块内去重；
- force_create：已存在跳过、覆盖警告；
- DDL 输出：每表 `sql/{table}.sql`。

## 六、复现命令

```bash
# 环境
brew services start mysql@9.7
/opt/homebrew/opt/mysql@9.7/bin/mysql -u root -p123456 aiprod < example.sql

# 构建生成器
mvn -f generator/pom.xml -DskipTests package

# 校验（真实配置 / 示例配置）
./gen.sh --validate /tmp/cgt-test/generate-local-real.yaml
./gen.sh --validate /tmp/cgt-test/generate-local-example.yaml

# 生成（flat）
./gen.sh /tmp/cgt-test/generate-local-example.yaml
./gen.sh /tmp/cgt-test/generate-local-real.yaml

# 布局（aggregated / maven-module）
./gen.sh /tmp/cgt-test/generate-aggregated.yaml
./gen.sh /tmp/cgt-test/generate-maven.yaml

# 生成工程编译验证
cd /tmp/cgt-test/out-example && mvn -DskipTests compile
cd /tmp/cgt-test/out-real && mvn -DskipTests compile
```

> 配置副本位于 /tmp/cgt-test/*.yaml（指向本地 127.0.0.1:3306）；输出工程位于 /tmp/cgt-test/out-*。
