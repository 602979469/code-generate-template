### 1.2 命名与类型默认映射

- 表名 → ModelName：snake → PascalCase（`chat_message` → `ChatMessage`）；
- 字段名 → Java 字段：snake → camelCase（`create_time` → `createTime`）；
- 数据库类型 → Java 类型：沿用 1.0 默认映射表（`varchar→String`、`datetime→LocalDateTime`、`bigint→Long`…）；
- 配置文件只做**列级覆盖**（`columns`），默认映射不开放为风格开关。

### 1.3 共享类归属（2.0 调整点）

- core-model 里的**公共类**（`BaseModel`、`ErrorCode`、`UserContext`、`BaseEnum` 等跨业务域共享的模型/接口）迁到 **common-framework**；
- core-model 只保留业务域相关的 `domain / param`（每表生成的领域模型与查询参数）；
- common-framework / common-util 是 2.0 的共享层与插件代码落点，不挂业务模块。

### 1.4 模板渲染与防覆盖

- Freemarker 渲染，文件写出前做幂等控制：已存在且未配置 `force_create` → 跳过；`force_create: true` → 覆盖并警告；
- 每张表独立判定成功 / 跳过 / 强制覆盖，互不影响。

## 二、路径策略（统一口径 + 差异化）

### 2.1 策略接口（数据驱动，不含层/文件判断）

```java
public interface LayoutStrategy {
    String id();                            // "flat" | "aggregated" | "maven-module"
    String packagePrefix();                 // "" | "modules"
    Path   moduleRoot(Path outputDir, String module);  // 业务层所在根目录
}
```

### 2.2 统一口径

```java
public PathSpec resolve(String layerPackage, String sub, String module) {
    String pkg;
    if (layerPackage.startsWith("common.")) {
        // 共享层：不挂业务模块，根固定为 common 模块
        pkg = basePackage + "." + layerPackage + "." + sub;
    } else if (isBlank(module)) {
        // 未分配业务模块：路径不含模块段（flat 等价 1.0 原样）
        pkg = basePackage + "." + layerPackage + "." + sub;
    } else if (layout.equals("flat")) {
        pkg = basePackage + "." + layerPackage + "." + module + "." + sub;
    } else {
        // aggregated / maven-module：包路径一致，仅根目录不同
        pkg = basePackage + ".modules." + module + "." + layerPackage + "." + sub;
    }
    return new PathSpec(strategy.moduleRoot(outputDir, module), pkg);
}
```

### 2.3 三种模式参数

| 模式 | packagePrefix | moduleRoot（业务层） | 业务层包路径 |
| :--- | :--- | :--- | :--- |
| flat | `""` | 1.0 层模块（common/dal、core/model、web…，不新建） | `{basePackage}.{层包}.{module}.{子包}` |
| aggregated | `modules` | `{outputDir}/modules/{projectArtifactPrefix}-{module}/` | `{basePackage}.modules.{module}.{层包}.{子包}` |
| maven-module | `modules` | `{outputDir}/{projectArtifactPrefix}-{module}/`（平铺） | `{basePackage}.modules.{module}.{层包}.{子包}` |

### 2.4 注册与路由

- 配置 `projectStyle` + `moduleLayout` 组合为策略 id：`monolith:flat` / `monolith:aggregated` / `monolith:maven-module`；未配置 = `monolith:flat`；
- `microservice:*` 注册占位 id，配置到即抛「暂未支持」；
- 策略通过注册表（`Map<String, LayoutStrategy>`）按 id 取实例，生成流程只依赖接口，无分支判断。

## 三、插件机制（协议先行，第一版不落地具体插件）

### 3.1 配置

```yaml
plugins:
  - name: sa-token   # config 参数位预留（第一版固定模板）
```

### 3.2 插件目录协议

`templates/plugins/{name}/` 下：

- `plugin.yaml`：插件名、激活配置项、**目标文件清单**（每项 = 目标模块 + 子包 + 模板/静态内容 + 类名规则或固定文件名）、**maven 依赖**（gav + `targetPom: root | 模块名`）；
- 对应 `.ftl` / 静态文件。

### 3.3 生成行为

- 工程级、一次性：骨架初始化后生成一次，**已存在的文件跳过、不覆盖**；
- 插件文件目标 = `common-framework` / `common-util`（2.0 共享层），路径一律走统一 `resolve()`，插件自身不拼路径；
- 插件不负责表：涉及表的业务走正常 `tables:` 生成，不进入插件机制。

### 3.4 本期范围

- 只落地插件协议与路由骨架；**不迁移 sa-token 等具体插件/业务代码**；
- 迁移范围仅限：CRUD 相关代码（1.1 层目录表）与 CRUD 用到的工具类规范（common-util 的 `AssertUtil` / `LoggerUtil` / `ConvertUtil` / `ApiResult` 等使用约定）。

## 四、扩展点

| 扩展方向 | 改动位置 | 成本 |
| :--- | :--- | :--- |
| 新增一层（如 gateway） | 1.1 层目录表加一行（层 id / 子包 / 类名规则 / 模板）+ 模板文件 | 小 |
| 新增布局模式 | 新增 `LayoutStrategy` 实现类 + 注册表一行 | 小 |
| microservice（多服务/多仓） | 策略 + 骨架差异（每服务 bootstrap/pom/Dockerfile），二期 | 中 |
| 具体插件（sa-token 等） | 按 3.2 协议新增插件目录，生成器零改动 | 中 |
