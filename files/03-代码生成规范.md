# 代码生成规范

> 版本：v2.0 | 生效日期：2026-08 | 参考基线：aiplatform（1.0）
> 生成代码是业务工程的一部分，必须遵守本文与项目 AGENTS 军规。**结构、命名、模板全部照 1.0，不引入新风格开关**；唯一结构调整：core-model 的公共类迁到 common-framework。

---

## 一、命名规范

- 模型名无前缀：表名 snake → PascalCase（`chat_message` → `ChatMessage`），不拼 Biz 等前缀；
- 字段名 snake → camelCase（`create_time` → `createTime`）；
- 各层类名固定规则（aiplatform 真实文件集）：

| 层 | 类名规则 | 示例 |
| :--- | :--- | :--- |
| common-dal | `{ModelName}DO` / `{ModelName}Mapper` / `{ModelName}Mapper.xml` / `{ModelName}DalQuery` | `ChatMessageDO` |
| core-model | `{ModelName}`（domain）/ `{ModelName}QueryParam`（param） | `ChatMessage` / `ChatMessageQueryParam` |
| core-repository | `{ModelName}Repository` / `RepositoryImpl` / `Convertor` | `ChatMessageRepository` |
| core-service | `{ModelName}Service` / `ServiceImpl` | `ChatMessageService` |
| biz | `{ModelName}Manager` / `ManagerImpl` | `ChatMessageManager` |
| web | `{ModelName}Controller` / `ParamChecker` / `{Action}Request` / `Response` / `Assembler` | `ChatMessageController` |

## 二、类型映射与列级配置

### 2.1 数据库默认映射（未配置 `columns` 时）

| 数据库类型 | Java 类型 |
| :--- | :--- |
| `bigint` | `Long` |
| `int` / `smallint` / `tinyint` | `Integer` |
| `varchar` / `char` / `text` / `longtext` | `String` |
| `datetime` / `timestamp` | `LocalDateTime` |
| `date` | `LocalDate` |
| `decimal` / `numeric` | `BigDecimal` |
| `double` / `float` | `Double` |
| `bit` / `boolean` | `Boolean` |
| `json` | `String`（原始 JSON 文本） |

优先级：列级 `columns` 配置 > 数据库默认映射。

### 2.2 枚举（`type: enum`）

- `enum.className` 必填且为合法 Java 类名；`values` 中 `code` / `name` / `desc` 均必填，`code` 与 `name` 不可重复；
- 枚举 code 类型按列推断：int 族 → `Integer`、bigint → `Long`、其余 → `String`，`code` 必须能被解析；
- DO 保持原始类型（Integer/String），Model/DTO 用枚举，Convertor 自动 `fromCode(...)` / `getCode()` 双向转换；
- 同名枚举已存在且未 `force_create` → 跳过该枚举文件（不覆盖），多表共用同一枚举时只生成一次。

### 2.3 JSON（`type: json / jsonObject / jsonArray`）

- `json`：保持原始字符串，不解析；
- `jsonObject`：`javaObject` 为目标 POJO 全限定名或 `Map<String, Object>`；`javaObject: String` 非法（用 `type: json`）；
- `jsonArray`：`javaObject` 为元素类型（POJO / `String` / `Integer` 等），生成 `List<X>`；
- 绑定的 POJO 由业务方自行创建，生成器不产出；
- Convertor 自动用 `JsonUtil.parseArray / parseObject / parseMap / toJson` 互转。

### 2.4 强制类型转换（`type: 具体 Java 类型`）

- 支持 `Integer / Long / BigDecimal / String / Double / Boolean / Float / Short / Byte / Character`；
- DO 类型不变，Model/DTO 为指定类型；转换统一使用 Hutool `Convert`（`toInt / toLong / toStr` 等），**禁止裸 `Integer.valueOf` 等**；
- 溢出/解析风险由配置人负责，生成器只保证组合可编译。

## 三、分层职责与写法约定

| 层 | 职责 | 关键约定 |
| :--- | :--- | :--- |
| common-dal | DO / Mapper / Mapper.xml / DalQuery | DO 永远保持数据库原始类型（“DO 永不漂移”）；Mapper.xml 一律 `#{}`；DalQuery `extends DalPageQuery` |
| core-model | domain / param | domain 为充血模型，**禁止 Spring/MyBatis 注解**；QueryParam 保持查询原始类型 |
| core-repository | Repository / Impl / Convertor | 唯一允许操作 Mapper 的层；返回 Model 不返回 DO；`insert` 返回回填主键后的 Model，`update/updateByCondition/deleteByXxx` 返回 `int` |
| core-service | Service / Impl | 领域服务，禁止注入 Mapper |
| biz | Manager / Impl | 应用服务/事务边界，多写事务用 `BizTemplate.execute(transactionTemplate, ...)` |
| web | Controller / ParamChecker / DTO / Assembler | Controller 零业务逻辑，统一 `ApiTemplate.execute + Callback`；校验在 `beforeService` 调 ParamChecker；Assembler 首行判空、敏感列不进响应 |
| bootstrap | Application / application.yml | 启动层，不写业务代码 |

依赖方向（自下而上）：`common-util` 最底层 → `core-model` → `common-dal / core-repository` → `core-service` → `biz` → `web`；`web` 不依赖 `common-dal / core-repository`。

## 四、共享类与工具类规范（2.0 调整点）

- core-model 的**公共类**（`BaseModel`、`BaseEnum`、`ErrorCode`、`UserContext` 等跨业务域共享的模型/接口）迁到 **common-framework**；
- 每表生成的业务枚举（`UserTypeEnum` 等）留在业务模块的 `core-model/enums`；
- common-util 基础组件：`AssertUtil`、`LoggerUtil`、`ConvertUtil`、`ParamValidator`、`Result` / `PageResult`；web 返回体/模板统一 `ApiResult` / `ApiTemplate`；
- 日志统一 `LoggerUtil`，**禁止直接 `LoggerFactory`**；
- 异常统一 `BizException` + ErrorCode（公共异常码放 common-framework），禁止在全局拦截器对 code 做存在性校验。

---

## 五、SQL 与审计列规范

- `create_time` / `update_time` 由数据库自动维护（`DEFAULT CURRENT_TIMESTAMP [ON UPDATE CURRENT_TIMESTAMP]`）；未满足时生成代码在 INSERT/UPDATE 显式 `NOW()` 并输出警告，不阻塞生成；
- `create_by` / `update_by` / `del_flag` 为保留审计列，**不生成 DO 字段**；
- 逻辑删除：`logicDelete` 配置的列必须真实存在才启用；缺失时生成器输出警告并**退化为物理删除**（不静默忽略）；
- 查询条件当前全部等值 `=`（含 varchar），另含创建/更新时间区间（`createTimeBegin / createTimeEnd / updateTimeBegin / updateTimeEnd`）与分页。

## 六、校验与幂等规范

### 6.1 入参校验

- NOT NULL 且无默认值的列：DTO 生成 `@NotBlank`（字符串）/ `@NotNull`（其他类型）+ varchar `@Size(max)`；
- 非自增主键在 CreateRequest 自动必填，INSERT 显式携带主键列。

### 6.2 防覆盖

- 骨架初始化：已存在文件跳过，重复运行安全；
- 表级生成：DO 已存在且未配置 `force_create` → 整表跳过；同名枚举已存在 → 只跳过该枚举文件；`force_create: true` → 覆盖该表全部文件并警告；
- `sql/` 下 DDL 文件遵循同样的跳过 / 强制覆盖规则；
- `generateController: false`（内部表）：不生成 web 层与 biz 层文件。

---

## 七、路径与模块归属

- 三种布局（flat / aggregated / maven-module）的 Maven 模块划分、包路径与目录结构见《02-代码风格与模块设计》与《04-路径策略与插件机制设计》；
- `common` 层（dal / framework / util / integration）不挂业务模块，始终 `{basePackage}.common.*`；
- 业务层 `module` 段可选：不填 = 路径不含业务模块段（flat 下等价 1.0 原样）。
